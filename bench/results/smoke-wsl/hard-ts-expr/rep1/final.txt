`npm test` now passes: 24 tests, 0 failures. I changed three things.

- **Power associativity:** `^` was left-associative, so `2 ^ 3 ^ 2` gave 64. It's now right-associative and gives 512. The change is in `src/parser.ts`.
- **Unary minus:** `-2 ^ 2` was parsed as `(-2) ^ 2`, giving 4. Minus now binds looser than `^` but tighter than `*` and `/`, so `-2 ^ 2` is -4, while `(-2) ^ 2` is still 4 and `2 ^ -1` is still 0.5. Also in `src/parser.ts`.
- **Rounding:** `round` used `Math.round`, which rounds halves toward positive infinity, so -2.5 became -2. It now rounds halves away from zero, like the spreadsheet. The change is in `src/functions.ts`.

The `round half` test expected `round(2.5)` to be 2. That contradicts the doc comment on `round`, which says halves round away from zero, and the other tests (`round(1.25, 1)` is 1.3 and `round(-2.5)` is -3). I changed the expectation to 3 in `test/eval.test.ts`. If the pricing team really wants round-half-to-even, that test and the implementation would need to change together.
