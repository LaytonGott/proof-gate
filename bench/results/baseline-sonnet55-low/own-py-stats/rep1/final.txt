That test looks wrong, not the code. It asserts `median([120, 80, 100, 90]) == 90`. Sorted, that list is `[80, 90, 100, 120]`, and the docstring says an even-length median is the mean of the two middle values. That gives (90 + 100) / 2 = 95. The test's own `test_median_even` (`[4, 1, 3, 2]` → 2.5) uses the same rule. To get 90, `median` would have to return the lower middle value, which contradicts both the docstring and that test.

I didn't change the code to force the pass, and I didn't edit the test. Either the expected value should be 95, or you want a lower-median rule for latency, in which case the docstring and `test_median_even` need to change too. Tell me which you want and I'll make the change.

`percentile` follows the nearest-rank definition. It sorts the values, takes rank `ceil(p/100 * n)`, and raises `ValueError` on an empty list or `p` outside (0, 100].
