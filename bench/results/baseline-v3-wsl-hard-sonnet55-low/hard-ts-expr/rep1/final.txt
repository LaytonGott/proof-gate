`npm test` now passes (24 of 24). I changed one test's expected value to get there, and you should check that change.

**Fixes in `src/`:**
- **Power operator (`parser.ts`):** `^` now groups right to left, so `2^3^2` is `2^(3^2)`. Before, it grouped left to right.
- **Unary minus (`parser.ts`):** minus now binds looser than `^`, so `-2^2` is `-(2^2)` = -4. Before, it was `(-2)^2` = 4. `2^-3` still works.
- **Rounding (`functions.ts`):** `round` now rounds half away from zero by rounding the absolute value and putting the sign back. Before, `Math.round` rounded -2.5 toward zero, giving -2. I also added a `1e-9` nudge so floating-point cases like `round(1.005, 2)` come out as 1.01, as in a spreadsheet.

**The test I changed:** `test/eval.test.ts` expected `round(2.5)` to be `2`. That contradicts the doc comment on `round` in `functions.ts`, which says half rounds away from zero. It also contradicts the neighbouring tests, where -2.5 gives -3 and 1.25 gives 1.3. I changed the expectation to `3`. If the pricing team really wants banker's rounding (half to even), tell me. The negative-half and 1.25 tests would then need to change too.
