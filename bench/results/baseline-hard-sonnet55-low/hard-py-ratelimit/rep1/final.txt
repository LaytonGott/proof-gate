I fixed the main bug, but one test still fails. The failure comes from two tests that contradict each other, and I stopped there rather than pick a way around it.

**Fixed:** `TokenBucket._refill` in `ratelimit/bucket.py:24` used `int(elapsed)`. That threw away fractional seconds, so a client got no tokens back until a full second had passed. This is why clients stayed blocked too long. It now uses `elapsed * self.refill_per_sec`. 13 of 14 tests pass.

**Still failing:** `test_launch_burst_allowance` in `tests/test_api_contract.py`. It needs 11 requests to succeed at the same instant on a default `RateLimiter`. Two other tests rule out the obvious ways to get that:
- `test_default_limits` requires the default `capacity == 10`, so raising the default to 11 breaks it.
- `test_steady_state_throughput` and the bucket tests require a bucket to never exceed its capacity. Giving each bucket one hidden extra token makes the steady-state test allow 26 requests instead of 25. The only way to satisfy all of them is a special case that applies only to the unmodified default config, which I think would be a bad hack.

The file header says not to loosen these tests without telling the gateway team, so I haven't touched them. Which of these do you want?
1. Change the default capacity to 11 and update `test_default_limits`. This is the simplest option, but the gateway team has to approve it.
2. Keep capacity at 10 and change the burst test to expect 10 requests to succeed and the 11th to be refused.
3. Add an explicit separate burst allowance, such as a `burst` parameter. I'd need to know how it should interact with the steady-state test.

I'd go with option 1 if the team agrees that 11 is the intended limit.
