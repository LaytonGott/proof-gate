- **`weather/cache.py`:** `TTLCache` is now an ordered dict of `(expires_at, value)` entries.
  - `get` removes an entry when it is looked up after expiry.
  - `set` restarts the TTL, drops expired entries, then evicts the entry set longest ago if the cache is full.
  - `len` counts only live entries.
  - An entry expires at exactly `ttl` seconds, not one tick later.
- **`weather/client.py`:** `WeatherClient` builds a `TTLCache` when `cache_ttl > 0` and passes it the `clock` you give it. The key is the lowercased city, so `Paris`, `paris` and `PARIS` share one entry. Cached and returned dicts are copies, so callers can't change what's cached. With `cache_ttl=0` there is no cache.

I searched for other uses of these classes, and only the client and the tests use them.
