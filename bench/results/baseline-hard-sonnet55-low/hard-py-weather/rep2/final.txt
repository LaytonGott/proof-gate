**`weather/cache.py`**
- `TTLCache` follows the spec in its docstring.
- An entry expires exactly `ttl` seconds after it was set.
- `set` on an existing key restarts its TTL and makes it the newest entry.
- When the cache is full, expired entries are dropped first, then the entry set longest ago is evicted.
- `len()` counts only live entries.

**`weather/client.py`**
- `WeatherClient` caches responses per city with a case-insensitive key, so "Paris", "paris" and "PARIS" share one entry.
- It returns copies of the cached dict, so a caller can't change what's stored.
- `cache_ttl=0` turns caching off, and the `clock` argument is passed through to the cache.

Nothing else in the repo calls these, so no other code needed updating.
